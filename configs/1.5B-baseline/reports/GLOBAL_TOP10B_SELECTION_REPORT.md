# Global Top-10B selections — selection report

Three anchor-free 1.5B baselines, each selecting its entire ~10B TRAIN-token corpus from the Quality-Base universe with one score, compared with the existing fastText Quality-Base. Generated by `tools/kys_raw/render_selection_report.py` from `selection_report.json` (`tools/kys_raw/report_global_top10b.py`) and `selection_manifest.json` (`tools/kys_raw/select_global_top10b.py`). These analyses describe the *data*; they say nothing about downstream performance.

## 1. Definition

- **Scored pool:** `blab-jhu/KYS-DCLM-Refinedweb-100M-Scored@dcbbc360`, 99,949,162 rows (the table every KYS selection ran over).
- **Eligible universe:** all rows minus the 50,000-doc validation holdout = **99,899,162 docs, 95,309,940,485 TRAIN tokens**. The holdout is `sort(default_rng(SeedSequence(42).spawn(8)[0]).choice(N, 50_000, replace=False))`, exactly as `projects/rewrite/04_select/select_10b.py`, with sorted-id sha256 `c234317b706bed7d…`. No other exclusion; in particular the 5M analysis sample is **not** excluded, as in the original. The scorer-training documents were already removed from the pool itself (§2b).
- **TRAIN tokens:** `tokens-llama2 + 1`, i.e. Llama-2 length without special tokens, plus the one `</s>` datatrove appends.
- **Scores.** Each is the pipeline's tie-aware global percentile, `rankdata(raw, "average") / 99,949,162`. The reference population is all scored rows, validation docs included; higher is better.
  - `raw_top10b_fineweb_edu`: `fineweb-edu-ranking-v2`.
  - `raw_top10b_modernbert`: `modernbert-ranking-v2`.
  - `raw_top10b_consensus`: `q = ((ft + fw + mb) / 3.0).astype(float32)` over the three v2 percentiles, the same expression as `select_10b.py` / `select_s5.py`. Raw scores are not averaged. There is no variance term, floor, quota, domain restriction or rewriting.
- **Order:** score descending (compared in float64). Ties are broken by `default_rng(SeedSequence(42).spawn(8)[1]).permutation(N)` ascending, i.e. `select_10b.order_desc`.
- **Cutoff:** keep whole documents along the order until cumulative TRAIN tokens first reach 10,000,000,000 (`select_10b.fill_to`, `searchsorted(..., "left")`). Overshoot is less than one document.
- **No anchor:** the anchor is not added; a setting contains anchor documents only if its own score ranks them in (§4).
- **Digest conventions:**
  - `selection_order_sha256`: sha256 of selected doc_id (scored pool, int64 LE) in selection order
  - `docset_sha256`: sha256 of selected doc_id sorted ascending (int64 LE)
  - `orig_docset_sha256`: sha256 of selected orig_doc_id sorted ascending (int64 LE)

## 2. The existing fastText Quality-Base under the same conventions

- **Reconstruction.** The original Quality-Base is anchor (fastText prefix to 5e9) + the next 5e9 along the same order. Rebuilt with the rules above, it has:
  - 7,253,187 docs and 10,000,003,137 TRAIN tokens (anchor 4,120,164 / 5,000,002,332, block 3,133,023 / 5,000,000,805);
  - doc-set sha256 `90252ee58ad4b298adadb7dfd0dfd9ba5fe01ed595fa62cd5c1a53947e4c2a22`;
  - the same digest as the published `wytro/Know-Your-Sources/quality_base/metadata.json` `doc_id_digest_sha256`;
  - an anchor part identical to the published anchor: **True**.
- **A single global fastText Top-10B** (`fill_to(order, 1e10)`) is 7,253,184 docs and 10,000,000,865 TRAIN tokens (overshoot 865). It is a subset of Quality-Base: **True**, differing by **3 documents / 2,272 tokens** at the tail.
- **Why they differ.** The two-stage fill targets a cumulative 10,000,002,332 (5e9 + the anchor's 2,332 overshoot + 5e9) instead of 1e10.
- **Consequence.** Quality-Base *is* the global fastText Top-10B up to those 3 tail documents (0.00002% of tokens), so it is the matching fastText comparator for the three new arms. Its data **order** differs: the v2 Quality-Base trained on the `10B-base-shuf42` shuffle of that set.

## 2b. Scorer-training data, the 5M analysis sample, and the source universe

Audited from the scorer pipeline's own files and recomputed from document IDs; scripts and JSON in `configs/1.5B-baseline/reports/scorer_training_audit/` (nanotron repo).

**What the ModernBERT score is trained on (verified).**
- `modernbert` = a Ridge(α=1) head, trained by this project, on L2-normalised mean-pooled embeddings of the frozen external `nomic-ai/modernbert-embed-base` (`projects/rewrite/01_explore/score_modernbert.py`).
- Training rows: **50,427** Claude-Haiku-labelled documents (49,998 DCLM-RefinedWeb + 218 OpenWebMath + 211 algebraic-stack). The stored `model_meta.json` records `n_train: 50427`; a refit on all 50,427 rows reproduces the shipped coefficients (max |Δ| 2.1e-4), a refit on the 40,340 "train" split does not (0.56). So the "val" split was also fit; there was no separate calibration set.
- The 50,000 DCLM documents picked for labelling (of which 49,998 were scored and used) were drawn from the raw 100M pool, seed 42.
- **All of them were removed from the pool** before any scoring or selection: the 50,838 rows removed by `00_TMP/merge_remove_50k.py` are every row whose first 4,000 characters (sha1) match a labelled document (50,000 / 50,000 picks and 49,998 / 49,998 training documents are in the removed set; 838 further rows are prefix-duplicates). Present in the published pool: **0** training documents, so **0** in the validation holdout, in any selection and in any corpus.
- Not checked: near-duplicates whose first 4,000 characters differ; any overlap with the external embedder's own pretraining data (it only affects frozen features).

**The ~5M analysis sample (verified).**
- Drawn by `ppl_quality/sampling_5m/sample_5m.py`: `sort(default_rng(42).choice(100_000_000, 5_000_000))` over the raw pool. Re-derived here; the re-derivation matches the sample's URLs (1,000,000 / 1,000,000 checked in two shards) and the independently built exclusion table (all 5,000,000 positions).
- Used for score/topic analysis (fastText, FineWeb-Edu, perplexity, an earlier analysis-only Ridge, Luxical clusters). **No code trains, validates or calibrates the production ModernBERT head on it**; the embedder card's "5M sample" refers to Nomic's own contrastive data, not this one.
- It was **not removed**: 4,997,471 of its documents are in the published pool (4,998,853 counting duplicate crawl copies, the figure the 3B plan quotes). The original 1.5B selection (`select_10b.py` l.202-205) excluded only the validation holdout; so did every later selection. These baselines therefore keep it, **for comparability with Quality-Base**; no new exclusion is introduced.
